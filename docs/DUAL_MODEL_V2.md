# 双模型评分对比与独立消融批次 v2

2026-11-16 版本改为双模型评分协议，不采用人工评分。当前目标为第一模型 qwen3.8-27b 与第二模型 kimi-k3 的评分对比，以及第二模型视角下四组重写条件的探索性变化。两个模型均沿用当前 DashScope 兼容端点。不同模型名不证明训练独立，评分一致不证明客观正确。

## 新旧批次边界

- 2026-11-13 旧数据、人工表、失败和报告原样归档，作为历史记录；不再要求填写人工表。
- 新批次复用 data/exploration_v1.jsonl 的十篇原稿，独立输出到 runs/dual_v2_20261116，不与旧批次择优拼接。样本为 AI 编写的 dev 文本，质量层次是设计意图，不是真值。
- 四组各十项：不重写基线、无反馈重写、相关性反馈、全维反馈。后三组均两轮评分、中间一次重写；基线保留原文仅评分一轮。
- 第一模型与生成器使用 qwen3.8-27b；评测温度 0、生成温度 .3；rubric-v3 和 .3/.2/.2/.3 权重不变。每节点一次，网络阶段读超时 180 秒，输出 2048 token。
- 同原稿内条件顺序及原稿顺序以 seed=20261116 固定随机化；每条件一次重写实现，不宣称随机种子能使服务端模型确定复现。
- 原消融请求上界 310；第二裁判对十篇原稿及最多三十篇修订稿按题目+全文去重，最多 40 次；该批次上限为 350 次。没有额外模型测试调用、无隐藏 HTTP 重试。每次失败也占用尝试预算。

## 网络处理

src/network_guard.py 提供不带鉴权的 HEAD 预检。最多三次、1/2 秒退避，需连续两次获得非重定向、非 429/5xx 的 HTTP 响应才继续。400/401/403/404/405 可以证明该次连接收到响应，不能验证密钥或模型权限。TLS 保持校验，不修改系统 DNS、hosts 或代理。

生成与第一裁判各自复用线程安全 HTTPX 连接池，最多四条并发连接、keepalive 120 秒。四维仍并行。连接建立与连接池等待上限 15 秒，不用加长连接超时掩盖域名故障。连接复用减少重复握手机会，但不保证网络稳定。

每个样本块前预检，任意 provider_error 后保存当前任务并暂停整批，不启动下个任务；同一并行超级步中已发出的四条请求可能继续完成。结构/证据解析失败按失败保留并继续下一条件，不重试以获得更好分数。

所有推理尝试写入 fsync 日志；任务发起前先写 started 标记。显式 --resume 只处理尚未开始的任务，已完成失败不会补跑。有 started 无结果的崩溃任务视为是否计费未知，阻止自动重放，需检查日志。运行锁阻止同时启动两个进程；异常退出留下的锁需先确认没有进程和未归档请求再人工处理。

## 第二裁判与指标

第二模型仅接收题目、文本、同样的四维标准，不发送第一模型分数、反馈、条件名、设计层次或来源模型名。每篇一次联合四维 JSON，温度 0、输出 4096 token、每次一次尝试。原模型每维单独调用，第二模型联合调用；所以不能把差异只归因于模型，提示布局是混杂因素。

- 原稿一致性：每篇原稿的第一模型第一轮评分先在条件内观察取均值，与第二模型原稿评分组成一个配对。逐维及总分 MAE、Spearman；无真人真值，MAE 称“模型分歧”而非准确率。
- 最终文本一致性：原稿为聚类单位，对该原稿成功且有双评分的最终文本取均值，再形成十个以内的独立配对，避免把四十篇相关文本当成独立样本。
- 主消融比较：全维反馈 vs 无反馈。逐篇配对报告两个模型各自的分数差、改善/持平/退化、失败配对、尚未执行和未评分配对。另报与相关性反馈及基线的比较，保留负结果。
- 各组相对同一原稿的第二模型变化仅描述成功样本；不同成功子集不能直接比较组均值。失败/缺失不算持平、不填零。
- 以原稿为单位 bootstrap，n<2 不报告差值区间、n<3 不报告一致性区间；n=10 区间仅作探索，不能宣称显著或验证完整系统。微小数值差不代表实际质量变化，持平容差 1e-12 仅处理浮点误差。
- Token 只取服务端 usage。未知保留 null；无真实带日期的适用价表，不计算货币费用。当前批次不是串并行效率对照，不报告加速比。

## 命令

在项目根目录，先离线测试、再生成固定计划。prepare 不调用模型，既有路径会被拒绝。

~~~powershell
.venv/Scripts/python.exe -B -m src.dual_study prepare --dataset data/exploration_v1.jsonl --output-dir runs/dual_v2_20261116
.venv/Scripts/python.exe -B -u -m src.dual_study run --run-dir runs/dual_v2_20261116 --execute --max-calls 350
~~~

若网络故障暂停，检查 status.json、network_checks.jsonl 和 journals，连通恢复后可显式续跑；仍受同批累计 350 次上限约束，不覆盖任何失败：

~~~powershell
.venv/Scripts/python.exe -B -u -m src.dual_study run --run-dir runs/dual_v2_20261116 --execute --max-calls 350 --resume
.venv/Scripts/python.exe -B -m src.dual_study analyze --run-dir runs/dual_v2_20261116
~~~

DUAL_MODEL_REPORT.json 和 status.json 为派生视图可刷新；batch_plan、ablation/plan、source_snapshot、原始任务结果、judge_results、started 与 journals 保持归档。源码/运行环境改变后不允许续跑旧版本；须单独新批次及预算，避免混淆条件。
